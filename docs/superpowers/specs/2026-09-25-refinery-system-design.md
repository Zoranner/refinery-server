# Refinery 系统性设计与优化规格

## 背景

Refinery 是内网唯一的公网资料访问出口，对外只提供 MCP 和健康检查，固定四个工具：`web_search`、`web_read`、`web_explore`、`web_download`。2026 年 9 月 24 日的真实使用会话暴露出系统性问题，实测证据如下。

| 事实 | 观测值 | 来源 |
|---|---|---|
| 单会话 63 次 `web_read` 注入模型上下文的字符量 | 482,999 | 会话 `01a0d36d` 工具结果统计 |
| 其中 `links` 数组占比 | 189,367 字符，39% | 同上 |
| `links` 中 `html` 类型占比 | 1723 / 1729，已内联于 Markdown | 同上 |
| 同一次响应内的重复 URL 可省字符 | 38,969 | 同上 |
| `web_read` 设置 `max_chars` 后实际单次响应量 | 2.8 万至 3 万字符 | 同上 |
| 搜索结果污染 | Jina 查询 8 条中 4 条为成人站点；ReaderLM 查询 5 条中 3 条为医学论文 | 同上 |
| 服务整体不可用事故 | `POST /mcp` 返回 403 `Host header is not allowed`，同时 `/health` 返回 `{"status":"ok"}` | 会话 `01a0d360` |
| 读取超时 | 5 次读取在 60 秒后超时，全部报为 `-32602` | 会话 `01a0d36d` |

这些数字说明问题不在单点实现，而在契约、职责和可观测性三层同时缺失：对外文档承诺与实现不一致，能力判定把文件名当成权威，失败信息被压缩成单一错误码，响应体积没有预算约束，运行状态没有真实探针。

## 目标与非目标

目标是把当前"能调用"的状态提升为"长任务可靠、上下文代价可预测、失败可诊断、边界可验证"。

非目标保持不变：不引入数据库、任务队列、持久化归档、站点专用适配器；不改变免认证内网定位；不改变四个工具的名称，避免破坏已经安装的 `refinery-mcp` 扩展包。

## 质量目标

以下五条是本次设计的验收方向，每条都有可观测指标。

| 目标 | 指标 |
|---|---|
| 上下文经济 | 同等工作量下模型可见注入量较 09-24 基线下降 50% 以上 |
| 抽取质量 | 固定样本集上正文要点覆盖率不低于当前基线，噪声字符占比显著下降 |
| 失败可诊断 | 每类失败有唯一错误类别、发生阶段和可重试标记，不存在统一报参数错误 |
| 行为可复现 | 同一 URL 在 TTL 内返回一致内容；上游镜像固定到 digest |
| 边界可验证 | 就绪探针覆盖 MCP 初始化；部署后自检能发现 Host、Origin 或上游异常 |

## 系统分层与职责

```text
MCP 客户端
  |  Streamable HTTP：Host 校验、Origin 校验、就绪探针
  v
契约层        工具 schema、参数校验、响应投影、错误映射
  v
应用编排      search / read / explore / download-resource
  v
能力判定      URL 事实 + 响应事实 -> 处理路径
  v
获取与抽取    受控抓取器、抽取主路径、Reader 兜底
  v
规范化与预算  Markdown 归一化、链接投影、预算裁剪、统计
  v
缓存          内存、TTL、LRU、单飞、不落盘
  v
上游          SearXNG、Reader、公网站点
```

分层的判断标准是职责，不是代码目录。契约层只做协议转换和校验，不做抓取判断；能力判定只决定处理路径，不执行抓取；抽取层只负责产出正文，不决定输出多少；预算层是唯一决定返回多少的地方。

## 契约设计

### 工具参数

| 工具 | 参数 | 约束 |
|---|---|---|
| `web_search` | `query`、`page`、`limit`、`language`、`categories`、`time_range` | `page >= 1`，`limit` 1–20，后三项可选并原样传递 |
| `web_read` | `url`、`offset`、`max_chars`、`focus`、`links` | `max_chars` 1000–24000，默认 8000；`focus` 为可选 CSS 选择器；`links` 取 `resources` 或 `all` |
| `web_explore` | `url`、`limit` | `limit` 1–500，默认 100，必须真实暴露而不是硬编码 |
| `web_download` | `url` | 保持现状 |

所有范围与默认值必须写进 JSON Schema，客户端在调用前就能避开无效参数。字段说明保持一句话，避免工具描述长期占用上下文。

### 响应模型

成功响应继续使用 `target`、`extraction`、`download`、`pagination`、`diagnostics` 五个对象，同时做三项收缩。

恒为空的字段不再序列化。`diagnostics` 必须填真实值：`upstream_status`、`duration_ms`、`timeout_seconds`、`cache`、`warnings`。

每次调用只返回一份载荷。当前实现同时返回内容相同的 `content` 文本和 `structuredContent`，线缆传输与客户端解析都是双倍；在未声明 `outputSchema` 的情况下只返回 `content` 不违反协议。后续需要富渲染时，再按 `outputSchema` 增加结构化载荷。

### 链接投影

`links` 数组默认只返回资源型链接，即 `pdf`、`image` 和未知附件，按 URL 去重、上限 50 条，超出数量写入统计字段。普通页面链接继续由 Markdown 内联表达，不再重复投影。`links=all` 保留旧行为供特殊场景使用。

依据是 09-24 的统计：`links` 占注入量 39%，其中 99.5% 是已在 Markdown 中内联的页面链接，资源型链接只有 6 条、932 字符。

### 预算

`max_chars` 是当前分段 Markdown 的字符预算，链接与元数据另有独立上限，响应总预算由三者之和界定，不允许任一维度无限增长。响应增加统计字段，至少包含 Markdown 字符数、纳入与省略的链接条数、是否截断。

分段契约保持不变：`pagination.offset` 是本次起点，`pagination.next_offset` 是精确续读位置，`truncated` 表示是否还有内容。续读依赖缓存，缓存未命中时响应标记该事实，因为重新抓取的内容可能与上次不同。

### 错误模型

失败按 MCP 规范分成两类。

协议层只用 `-32602` 表示参数本身非法：缺少必填字段、越界、URL 格式错误。业务层统一返回 `CallToolResult` 的 `isError=true`，并在结构化内容中提供 `code`、`message`、`stage`、`retryable`。

工具错误的类别固定为：`invalid_request`、`blocked_target`、`upstream_unavailable`、`upstream_timeout`、`response_too_large`、`busy`、`internal`。`extraction_empty` 与 `extraction_blocked` 不是工具错误，它们是成功响应中 `extraction.status` 的取值，表示请求成功但没有可用正文，因此仍保留下载能力。当前把所有失败都映射为 `invalid_params` 的实现整体替换，不做逐分支打补丁。

## 内容获取与抽取

能力判定从"文件名裁决"改为"响应裁决"：URL 后缀只作提示，图片保持短路，未知后缀先尝试抽取，仅在抽取失败或正文为空时依据真实响应类型判定为仅可下载，并保留下载能力。这条改动直接消除 `.toml`、`.env`、`.sh` 一类文本被拒绝请求的情况。

抽取主路径由基准测量决定，不预先选定。候选有三条：Reader 现状、Reader 加 CSS 选择器聚焦、Refinery 自行受控抓取 HTML 后用 Rust 抽取库生成 Markdown。测量维度是正文要点覆盖率、噪声字符占比、耗时和失败率，样本为 20 至 30 个固定页面，覆盖代码托管、文档站、问答站、中文站点、纯文本、PDF 和 JS 重页面。

判定规则先定好：自建抽取只有在正文覆盖率不低于 Reader 且噪声占比明显更低时才成为主路径，否则 Reader 保持主路径，本次只做规范化与聚焦能力。规范化包含折叠多余空行与缩进、去掉追踪参数、合并重复链接块，全部是确定性变换，不做内容改写。

Reader 的定位随之调整为兜底：承担 JS 重页面、PDF，以及主路径失败或正文过短的情况。

## 缓存与可靠性

引入有界内存缓存，这是续读稳定和默认预算下调的前提。键为规范化 URL 加抽取模式，存储抽取后的正文与元数据；TTL 默认 10 分钟，条目数与总字节数都有上限，按 LRU 淘汰；同一键的并发请求合并为一次上游抓取；不落盘，重启失效。

缓存只解决重复抓取，不改变内容可能随上游变化的事实，因此响应必须显式报告命中状态。

超时按阶段分层：连接超时、目标抓取总时长、Reader 抽取预算各自独立，超时结果携带发生阶段。并发按用途分池，抓取、抽取与资源下载分别有界，超过上限返回 `busy`，不排队。

资源下载的 20 MiB 上限需要重新评估：base64 编码后膨胀到约 27 MiB，必须用真实 MCP 客户端验收后才能确定最终值。

## 搜索质量

安全搜索不再依赖部署默认值。`deploy/app/settings.yml` 当前为 `safe_search: 0`，而 SearXNG 支持按请求传 `safesearch`（0/1/2）、`categories` 和 `time_range`，因此搜索策略属于服务契约：默认以 `safesearch=1` 发起，允许调用方按需调整。

结果事实必须保留：每条结果的来源引擎、未响应的引擎、上游结果数。`source_status` 由真实情况决定，不再固定为 `ok`。结果按 URL 去重，摘要截断，`published_at` 为空时不序列化。

引擎集合需要收敛。当前部署启用 38 个未禁用引擎，通用类同时包含 Google、Bing、DuckDuckGo、Brave、Qwant、Startpage 等多路来源，是结果污染的主要嫌疑。收敛方案先测量再定：同一批查询分别用完整集合与收敛集合运行，对比有效结果比例，再决定保留清单。

## 可运维性

`/health` 继续表示进程存活，新增 `/ready` 表示链路可用，覆盖 Reader 与 SearXNG 可达性以及 MCP 初始化自检。

部署自检脚本在安装或升级后执行：MCP 初始化、`tools/list`、一次 `web_search` 冒烟，以及 Host 与 Origin 白名单和实际访问 authority 的一致性校验。09-24 的事故正是缺少这一步：客户端初始化失败后工具静默消失，几小时内没有任何自动检查发现。

部署边界同时收紧：Refinery、Reader、SearXNG 三个镜像固定到 digest；SearXNG 的 `secret_key` 从仓库常量改为部署时注入；版本事实保持单一来源，`Cargo.toml`、镜像 tag、Compose 与扩展包说明必须一致。扩展包当前声明 `0.3.0` 而仓库为 `0.2.0`，这类漂移要在流程上消除。

## 观测与诊断

每次响应携带工具名、目标主机、阶段、耗时、字节数和缓存命中状态。日志不记录正文、完整查询参数或凭据。诊断信息用于回答两个问题：失败发生在哪一层，以及调用方能否通过改参数解决。当前 `diagnostics` 三个字段恒为 `null`、失败信息只有一句 message 的状态必须结束。

## 验证策略

离线验证使用本地 stub 服务器模拟 SearXNG、Reader 与目标站点，覆盖错误矩阵、类型判定、预算裁剪、链接投影、缓存命中与单飞、并发上限和私网拒绝。

MCP 契约验证覆盖初始化、`tools/list`、四个工具的 `tools/call`、业务错误是否真的使用 `isError=true`、资源读取的元数据字段、Host 白名单和 Origin 拒绝。

抽取基准按固定样本集执行，产出可重复的数字，作为主路径决策和后续回归的依据。

线上验收在部署机执行：冒烟脚本、复现 09-24 的调研场景，并对比同一场景的上下文注入量。本机没有 Docker，SearXNG 与 Reader 的全链路只能在部署机验证，这个边界写入验收记录。

## 交付顺序

工作按依赖关系排列，每项独立可测、可单独提交，前一项的结论不阻塞后一项的实现。

契约与一致性可以立即执行：错误模型、工具 schema、响应预算与链接投影、文档与实现对齐、`/ready` 探针。

抽取基准与规范化依赖实测数据：先测后改，产出主路径决策，再实现聚焦参数与确定性归一化。

可靠性在契约稳定后落地：缓存、单飞、并发分池、超时分层、资源上限复评。

搜索质量可以独立推进：安全搜索策略、来源事实、引擎集合收敛。

部署收紧与验收最后统一收口：镜像 digest、密钥外置、版本单一来源、自检脚本、线上复验。

## 需要确认的边界变更

本次设计会改变三条既有边界，需要明确同意后再进入实施。

引入有界内存缓存，从无状态变为有界临时状态。

可能引入 Rust 抽取依赖，把 Reader 从唯一抽取权威降为兜底，是否执行由基准结果决定。

搜索默认启用 `safesearch=1`，会改变当前返回的结果集合；引擎集合收敛同样会改变结果分布。

## 验收标准

同一调研场景的模型可见注入量较基线下降一半以上，且不丢失完成任务所需的信息。

参数错误只以 `-32602` 出现，上游失败、超时与阻断以 `isError=true` 加明确 `code` 出现，两者的比例可以通过日志核对。

`web_read` 能读取纯文本类未知后缀资源，图片与二进制仍返回仅可下载并保留下载能力。

续读在 TTL 内不重复抓取上游，缓存未命中时如实标记，不把缓存内容当作上游现状。

`/ready` 能发现 Host 白名单、Reader 或 SearXNG 故障，并给出可定位的阶段信息。

镜像固定到 digest，仓库内不存在运行密钥常量，版本声明在四个位置一致。
